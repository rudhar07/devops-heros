# Shell Scripting Homework - System Information Script

**Name:** Rudhar Bajaj
**Environment:** macOS 26.5.2 (Apple Silicon), hostname Rudhars-MacBook-Pro.local, `GNU bash, version 3.2.57(1)-release (arm64-apple-darwin25)`

A Bash script that prints the current date, hostname, username, disk usage and
running processes, takes input from the user with `read -p`, creates a directory
and a file, and saves the process list into that file with `>` redirection.

## Requirements covered

| Requirement from the assignment | Where it is done in the script |
| --- | --- |
| Prints the current date | `current_date=$(date)` then `echo "Date : $current_date"` |
| Prints the hostname | `host_name=$(hostname)` then `echo` |
| Prints the username | `login_user=$(whoami)` then `echo` |
| Prints the disk usage | `df -h` |
| Prints the running processes | `ps -eo pid,ppid,user,%cpu,%mem,stat,start,time,comm` |
| Uses variables to store and use data | `user_name`, `dir_name`, `current_date`, `host_name`, `login_user`, `file_name`, `process_count` |
| Takes user input using `read -p` | `read -p "Enter your name: " user_name` and `read -p "Enter a directory name ..." dir_name` |
| Creates a directory using `mkdir` | `mkdir -p "$dir_name"` |
| Creates a file using `touch` | `touch "$file_name"` |
| Stores the running processes in the file using `>` | `ps -eo ... > "$file_name"` |

## The script

```bash
#!/bin/bash
# system_info.sh
# Prints basic system information (date, hostname, username, disk usage,
# running processes), asks the user for input, creates a directory and a
# file, and saves the running-process list into that file using > redirection.

# ---------- 1. Take user input (read -p) ----------
read -p "Enter your name: " user_name
read -p "Enter a directory name to store the report: " dir_name

# ---------- 2. Store data in variables ----------
current_date=$(date)          # current date and time
host_name=$(hostname)         # machine name
login_user=$(whoami)          # user running the script
file_name="$dir_name/processes.txt"

# ---------- 3. Create the directory and the file ----------
mkdir -p "$dir_name"          # -p: no error if it already exists
touch "$file_name"            # create an empty file

# ---------- 4. Print system information ----------
echo "==================== SYSTEM INFORMATION ===================="
echo "Report for : $user_name"
echo "Date       : $current_date"
echo "Hostname   : $host_name"
echo "Username   : $login_user"
echo

echo "==================== DISK USAGE (df -h) ===================="
df -h
echo

echo "==================== RUNNING PROCESSES (ps) ================"
echo "(first 15 processes shown on screen, the full list goes to the file)"
ps -eo pid,ppid,user,%cpu,%mem,stat,start,time,comm | head -n 15
echo

# ---------- 5. Save running processes to the file with > ----------
ps -eo pid,ppid,user,%cpu,%mem,stat,start,time,comm > "$file_name"

process_count=$(wc -l < "$file_name")
echo "Saved $process_count lines of process information to: $file_name"
echo "Done."
```

## Running it

```bash
chmod +x system_info.sh     # give the file execute permission (only once)
./system_info.sh            # run it
```

## Commands used and what I understood

### `read -p`

```bash
read -p "Enter your name: " user_name
```

`read` waits for a line of input from the keyboard and stores it in a variable.
`-p` prints a prompt on the same line first, so I do not need a separate `echo`.
Whatever I type is available afterwards as `$user_name`. This is how a script
becomes interactive instead of having everything hard-coded.

### Variables

```bash
current_date=$(date)
file_name="$dir_name/processes.txt"
```

A variable is assigned with `name=value` and there must be no spaces around the
`=`. `$(command)` runs the command and stores its output in the variable, which
is how the date, hostname and username are captured once and reused. Quoting
`"$dir_name"` keeps the value intact even if it contains spaces.

### `mkdir`

```bash
mkdir -p "$dir_name"
```

Creates a directory. With `-p` it also creates missing parent directories and
does not fail if the directory already exists, so the script can be run twice
without an error.

### `touch`

```bash
touch "$file_name"
```

Creates an empty file if it does not exist, or just updates the modification
time if it does. I use it to make sure the report file exists before writing.

### `echo`

Prints text to the screen. I use it for the headings and for showing the values
stored in the variables. `echo` on its own prints an empty line, which I use to
separate sections.

### `df`

```bash
df -h
```

Shows disk space for every mounted filesystem. `-h` prints sizes in human
readable units (Gi, Mi) instead of raw 512-byte blocks. On macOS the columns are
`Size Used Avail Capacity`; on Linux they are `Size Used Avail Use%`, but the
command and flag are the same.

### `ps`

```bash
ps -eo pid,ppid,user,%cpu,%mem,stat,start,time,comm
```

Lists running processes. `-e` means every process, not just the ones started
from my terminal, and `-o` lets me choose the columns. I picked a fixed set of
columns because the default `ps aux` output includes full command lines that are
thousands of characters long on macOS, which made the report unreadable.

### `>` output redirection

```bash
ps -eo pid,ppid,user,%cpu,%mem,stat,start,time,comm > "$file_name"
```

`>` sends the standard output of a command into a file instead of the screen,
creating the file or overwriting it if it exists. `>>` would append instead.
This is the line that satisfies "store the running processes information in the
file". The script prints the first 15 lines to the screen with `| head -n 15`
and saves the complete list to the file.

## Key learnings

- A script is just the commands I would type, saved in a file with a `#!/bin/bash`
  first line and the execute bit set with `chmod +x`.
- `$(...)` captures command output into a variable, and quoting variables avoids
  surprises with spaces.
- `read -p` is the simplest way to take input, and `mkdir -p` / `touch` make
  file setup safe to repeat.
- `>` redirects output to a file and overwrites, `>>` appends, and `|` passes
  output to another command instead of a file.
