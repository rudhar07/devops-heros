# NOTE: real AWS would say GetObject=allowed, DeleteObject=implicitDeny here. LocalStack's answer looked wrong,
# so I tried two more things below to find out why.

$ aws --endpoint-url http://localhost:4566 iam simulate-custom-policy --policy-input-list file://s3-readonly-policy.json --action-names s3:GetObject s3:DeleteObject s3:ListBucket --resource-arns arn:aws:s3:::hw18-reports/q3.csv --query 'EvaluationResults[].{Action:EvalActionName,Decision:EvalDecision}' --output table

aws: [ERROR]: An error occurred (InternalFailure) when calling the SimulateCustomPolicy operation: The simulate_custom_policy action has not been implemented

# Checking whether it is just group membership: attach the same policy directly to the user and simulate again.

$ aws --endpoint-url http://localhost:4566 iam attach-user-policy --user-name hw18-alice --policy-arn arn:aws:iam::000000000000:policy/hw18-s3-reports-readonly

$ aws --endpoint-url http://localhost:4566 iam simulate-principal-policy --policy-source-arn arn:aws:iam::000000000000:user/hw18-alice --action-names s3:GetObject s3:DeleteObject --resource-arns arn:aws:s3:::hw18-reports/q3.csv --query 'EvaluationResults[].{Action:EvalActionName,Decision:EvalDecision}' --output table
-------------------------------------
|      SimulatePrincipalPolicy      |
+------------------+----------------+
|      Action      |   Decision     |
+------------------+----------------+
|  s3:GetObject    |  explicitDeny  |
|  s3:DeleteObject |  explicitDeny  |
+------------------+----------------+

# RESULT: even with the policy attached straight to the user, LocalStack community answers explicitDeny for
# everything, and simulate-custom-policy is not implemented. LocalStack community stores IAM objects but does
# not evaluate/enforce policies, so the allow/deny check stays conceptual (see 01-iam/README.md).
